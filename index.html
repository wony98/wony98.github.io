분야별 중간 판단 저장

선발·타선·불펜 등 10개 섹션을 차례로 읽고, 근거와 반론을 JSON으로 저장했습니다. 최종 단계가 이 기록을 다시 읽고 비교하도록 시험했습니다.

입력에서 빠진 자료와 판단 기록에서 빠진 근거를 나눠 확인할 수 있게 됐습니다. 근거 ID의 기록 여부는 검사했지만, 그 의미를 정확히 이해하고 판단에 반영했는지는 별도 문제로 남았습니다.

어떤 근거를 우선해 판단할 것인가

사전자료를 전달해도 종합 성적에 치우치거나, 근거가 부족하다며 판단을 과도하게 보류했습니다. 과거 경기에서 판단 방법을 뽑아 참고 사례로 연결했고, 다음 연구에서는 조건과 반론을 더 자세히 기록했습니다.

  1. 기준 추출 연구

    과거 경기에서 판단 방법 정리

    실제 플레이와 당시 사전정보를 대조했습니다. 어떤 조건을 함께 봐야 했는지, 어떤 반대 근거가 그 판단을 무효화하는지 남겼습니다. 경기 후에야 알게 된 사건은 사전 조건에서 제외했습니다.

  2. 검색 연구

    다른 경기의 당일 조건과 연결

    대상 경기보다 이전 사례만 검색했습니다. 과거 선수의 수치나 근거 번호를 그대로 쓰지 않고, 오늘 경기에서 대응하는 값과 출처에 다시 연결했습니다.

  3. 단계별 판정 실험

    양 팀의 승리 경로와 반론 비교

    필수조건 충족 여부와 기준을 무효화하는 조건을 따로 판단했습니다. 양 팀의 승리 경로, 서로 충돌하는 근거, 최종 선택 이유를 단계별로 저장했습니다.

판단기준 추출·검색·단계별 판정은 각각 별도 연구로 진행했습니다.

참고 기준을 찾았는지뿐 아니라, 오늘 경기에서 그 기준을 적용하거나 배제한 이유까지 추적할 수 있게 했습니다.

얼굴 블러와 모바일 업로드 개선 과정

수치 검사는 통과했는데 머리카락이 가려졌습니다.

문제
규격·처리 시간·블러 적용 프레임이 정상이어도 블러가 머리카락을 덮고, 화면 가장자리 일부 얼굴은 노출됐습니다.
원인
블러 영역이 머리카락까지 덮었습니다. 가장자리 얼굴 후보의 점수는 0.332~0.699였는데, 후단 임계값이 0.75여서 후보에서 빠졌습니다.
조치
같은 조건에서 블러 방식 4안을 비교해 얼굴 피부 분할을 선택하고, 임계값 0.60과 보간을 적용한 뒤 결과 영상을 육안 확인했습니다.
결과
검사한 8개 구간에서는 모두 블러가 적용됐습니다. 머리카락 보존을 우선하자 최종 처리 시간은 약 64초(63.840/64.068초)로 목표 60초를 넘었습니다.새로운 영상에서도 얼굴이 모두 가려지는지는 추가 검증이 필요합니다.

끝까지 만든 사람이 4명 중 1명이었습니다.

문제
초대한 10명 중 미용인 4명이 응답했습니다(8월 18~19일). 숏폼을 끝까지 만든 사람은 1명, 중단한 사람은 3명이었습니다.중단 사유는 사용법 3명·업로드 2명으로, 중복 응답이 가능했습니다.
원인
세부 설정을 다 이해해야 생성할 수 있었고, 모바일(iOS) 업로드가 실패했으며, 조정 화면이 복잡했습니다.
조치
세부 설정 없이 기본값으로 먼저 영상을 만들 수 있게 바꿨습니다. iOS 영상 선택 필터와 파일당 160MiB 업로드 상한, 요청 스트리밍도 고쳤습니다. 조정 화면은 프론트엔드 담당자와 함께 모바일 3단계로 다시 나눴습니다.
결과
수정 후 사용자 재평가는 하지 못했습니다.
업로드 오류와 배포 문제

공개 주소에서 영상 업로드와 복사가 실패했습니다. 원인 중 하나는 HTTPS가 필요한 브라우저 API였습니다. 폴백을 보완하고 DuckDNS, Caddy, Let's Encrypt로 HTTPS를 구성했습니다.

5초 이내 요청이 부동소수점 오차로 거부되는 문제에는 1e-6초 허용 오차를 뒀습니다. 한국어 자막이 네모로 표시되던 서버에는 글꼴을 추가했습니다.

문서만 바꿔도 모델을 약 3분간 다시 적재하던 배포 경로도 손봤습니다.

  • 설계 문서의 검증 목표 6항목: query 존재 / contexts 또는 evidence_units 존재 / doc_id·chunk_id·source_file 일관성 / 단일문서 문서 범위 / 다중문서 문서 수 / metadata direct answer 필드·값 존재

설계 6항목과 공개 구현의 차이

공개 validator는 필수 키와 자료형, 근거 필드의 누락을 검사합니다. 검색 결과가 있을 때는 근거가 참조한 순위도 확인합니다. 오류가 있으면 valid=false, 다중문서 수 부족은 경고로 기록합니다.

contexts는 빈 목록을 허용하고 evidence_units는 선택 항목입니다. 이 validator가 ID와 원문의 일치, 단일문서 범위, metadata_answer의 필드·값 유효성을 보장하지는 않습니다.

번들 생성 도구는 검증 옵션을 켰을 때 결과를 첨부합니다. 별도 오류 종료 옵션을 함께 켜면 산출물을 저장한 뒤, 검증 오류가 있을 때 오류 상태로 종료합니다.
