# Operating rules

Use this reference when a project needs approval gates, ownership boundaries, or cumulative records.

## Authority

- Read project policy before acting on another person's work.
- Distinguish permission to review from permission to edit, publish, merge, deploy, or message externally.
- A terminal request to finish work does not expand authority.

## Convergence

- Resolve technical disagreements with evidence between agents first.
- Verification and forming a judgment are not convergence. The addressed peer must respond, or the owner must explicitly override the pending exchange.
- Do not unilaterally mark an unrequested scope addition as accepted. Present it as a keep/revert proposal.
- Do not misclassify pre-existing baseline behavior as scope creep. Confirm against the diff, not the current file.
- Present one concise user briefing after the agents converge.
- Preserve explicit user approval boundaries for external writes and irreversible actions.

## Record ownership

- Assign a record owner only when the project requires cumulative history.
- Keep source submissions separate from reconstructed or reviewer-authored records.
- Mark reconstructed records clearly and never present them as the source author's submission.
